# inbox 增量读取与历史清理

T009 为 TideIsland 自己的元数据事件目录提供增量游标、容量 / 时间保留目标和“预览后应用”的清理。处理不读取或清理 Codex 的聊天目录、transcript、配置或信任记录。

## 增量读取

`readIncrementally(using:limits:)` 首次读取全部有界候选，后续仍枚举目录和文件属性，只读取、解码新增或变化的事件正文。游标保存在内存，不使用读取时间刷新事件时钟，也不按“最近 256 个文件”截断启动恢复。`readRecent(limit:)` 继续作为旧的有界读取接口保留，原生应用源码已改用增量路径。

文件身份包括设备、inode、大小、修改 / 变化时间的秒与纳秒、权限、所有者和链接数。同大小、恢复原 mtime 的修改也会通过 ctime 或 inode 变化重新读取；这依赖操作系统元数据，不是每次扫描都重新哈希正文。目录或管理标记身份变化时重新建立索引。

接口报告扫描、变化、实际解码、复用、移除、拒绝和跳过的数量，以及候选文件总字节数。损坏输入可缓存为拒绝项，文件修复后重新读取；超大文件不加载正文。只有合法 UUID 文件名、普通文件、当前用户所有且只有一个硬链接、内容通过 `EventCodec` 且 payload ID 与文件名匹配的事件才会交给会话层。符号链接、FIFO、目录、硬链接和其他名称不进入事件流。

默认最多索引 16,384 个候选文件，一次新读取正文预算 64 MiB，每个事件仍不超过 16 KiB。超限或读取过程中变化时，整个扫描失败，游标不推进，不返回不完整的启动批次。原生源码也只在会话层接收成功后提交新游标。文件移除会释放游标缓存，但不会自动清空当前进程已建立的会话 / 轮次状态。

目录枚举仍为 O(n)，游标不跨重启保存；这不是文件系统增量日志，也不提供无限历史保证。目录监听重建、完整故障恢复和跨重启状态持久化仍由 T010、T011 处理。

## 管理目录与写入

`prepare` / 事件写入会创建内容固定的 `.tide-island-inbox` 标记。标记在完整写入后原子发布，作为清理的范围标识和协作锁，不存放用户数据。旧的未标记目录可以只读导入；清理预览不会为它补建标记或创建目录，须由应用正常初始化后再使用清理。

事件写入使用受限权限的临时文件，在同一目录原子发布，最终事件文件为 `0600`。同一 UUID 的相同内容可重复写入；不同内容会被拒绝，不覆盖已经发布的事件。读写和清理通过稳定标记上的文件锁协调，写入者有限等待，读者 / 清理在忙碌时返回可重试结果。原生源码对短暂 busy 安排重试，不把它当作空 inbox。

文件访问使用持有的目录描述符和相对文件名，拒绝最终目录 / 事件的符号链接并复核身份。目录的父路径由用户配置，不提供针对同一用户恶意编辑器的权限隔离。清理应用期间不要用未参与协作锁的其他工具改写同一 inbox；POSIX unlink 不提供与外部编辑器之间的内容比较交换。

## 保留策略

默认目标：最多 4,096 个候选文件、32 MiB；历史年龄目标为 7 天。清理按整个 session 的事件链分组，不按单个文件的 mtime 或 UUID 大小决定删除。

以下会话链完整保留：

- 未结束的工作或待处理，包含长期无更新、已忽略及已置顶的记录。
- 尚未达到 T007 展示过期期限的本轮终态或退出记录。
- 最新观察未满 24 小时的历史，即使退出记录的展示已在 1 小时后结束。
- 存在未来时间、无法计算的时间差、未知轮次观察，或退出 / 缺少轮次身份后仍有无法可靠归属的工作观察。

其余已过期历史按最新事件时间从旧到新排列，先回收超过年龄目标的会话，再按文件数 / 字节目标回收更旧的过期会话。同时间按 session ID 稳定打平。清理不会只删除活跃会话的开始、并行工具、退役轮次或未绑定观察。

容量是**可回收数据的软目标**。受保护历史和无法识别的文件不会为了达标而被删除；预览 / 结果中的 `targetsMetAfterCleanup` / `targetsMet` 只说明文件数与字节容量目标是否满足，不能解释为硬磁盘配额或所有旧数据已移除。未知名称、损坏或超限记录均不自动清理，需单独排查。

已清理的过期 session 会从磁盘历史中被遗忘；当前进程的 registry 仍保留既有保护，但应用重启后无法从已删文件重建这些旧轮次。T011 尚未提供持久化终态标记或压缩 checkpoint；来源再次投递已遗忘旧事件时，仍受该恢复边界限制。正在处理的会话链不在本次回收范围内。

## 预览与应用

```bash
# 默认只读预览，不写目录、标记、备份或 Codex 配置
swift run tide-island-bridge inbox cleanup --inbox /absolute/path/to/TideIsland/Events

# 按刚才的 fingerprint 应用相同策略
swift run tide-island-bridge inbox cleanup --inbox /absolute/path/to/TideIsland/Events \
  --apply --expect FINGERPRINT

# 自定义保留目标；应用时必须再次带上完全相同的策略参数
swift run tide-island-bridge inbox cleanup --inbox /absolute/path/to/TideIsland/Events \
  --max-files 4096 --max-bytes 33554432 --max-age-days 7
```

预览 JSON 包含策略、受保护 / 拒绝 / 跳过数量、具体 UUID 文件名、删除原因、预计剩余容量和 fingerprint，不输出事件正文或聊天内容。指纹绑定目录及标记身份、候选文件元数据 / 内容摘要、策略和实际回收清单，不绑定预览发生的秒数。目录内容或回收清单变化会拒绝旧预览；不相关名称的文件不进入清理清单，也不会被删除。

CLI 应用会重新预览；原生源码保存用户看见的预览时刻和清单，不因等待而扩大清理对象。应用前重新读取并验证指纹，在协作排他锁内删除。每个 unlink 独立执行；文件系统失败可能产生部分清理，结果如实列出成功 / 失败数量和剩余容量，CLI 返回非零。它不是跨文件事务，异常中断后的完整恢复留在 T010，不能把部分失败当作全部回收成功。

超过默认读取上限时，可以显式增加 `--scan-limit`（最多 65,536）及 `--read-budget-bytes`（最多 256 MiB）后重新预览。仍超过上限时不会部分清理，需先归档历史。原生应用不在后台自动清理；源码提供“预览历史清理”和“清理已预览历史”，目录变化后使已有预览失效。

## 验证边界

新增共享层测试覆盖 300 个文件启动恢复、正文复用、同大小修改、拒绝缓存、读取预算、目录替换、标记与协作锁、并发写入、UUID 不覆盖、活跃 / 未绑定历史保护、整会话年龄 / 容量清理、旧预览和链接隔离。`check-inbox.py` 使用隔离目录检查 CLI 预览无副作用、精确应用、过期指纹、非法参数和提供方文件字节保留。

原生目录监听、busy 重试、预览控件和应用后的界面刷新尚未编译或实机运行，继续在 macOS 27.3 正式环境验收。本轮开发不对用户真实 inbox 执行清理，也不安装真实 hooks。

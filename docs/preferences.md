# 偏好、主动授权与登录启动

T021 提供设置窗口、菜单设置入口和有界本地偏好；共享层验证配置与展示策略，原生使用 UserDefaults、UserNotifications 和 ServiceManagement，实际保存、权限窗口及登录启动继续待 macOS 27.3 验收。

## 可配置内容

| 设置 | 默认 | 行为 |
| --- | --- | --- |
| 会话提醒 | 关闭 | 用户开启时才请求系统通知权限，允许后保存开关 |
| 待处理 / 本轮结束 | 两种都选中 | 仍受总开关、来源、已读 / 忽略与周期规则约束 |
| 声音 | 关闭 | 允许后按每次发送前的最新设置生成通知 |
| 安静时段 | 关闭 | 开启后初始 22:00—08:00，开始 / 结束可编辑，支持跨午夜 |
| 显示项目名称 | 开启 | 同时控制列表、实时活动负载和通知中的名称 |
| 历史状态显示 | 24 小时 | 可选 1、6、24 小时，仅缩短已解决状态的界面显示 |
| 登录时启动 | 首次不注册 | 系统实际状态决定开关，明确用户操作才 register / unregister |

设置页使用标准 Form、Toggle、Picker、DatePicker、SettingsLink。项目名称隐藏时显示“开发会话”；会话 ID、链接、原始观察和新鲜度不因改名而改变。原始会话元数据仍由既有接收 / checkpoint 管理，偏好是单独的展示及提醒配置。

历史显示设置处理 completed / failed / interrupted；会话退出记录仍受原有 1 小时来源期限约束。未确认的工作 / 待处理不会为满足显示时长而移除，5 分钟工作新鲜度保持独立。列表采用系统 TimelineView 的 60 秒显示节奏复核界面期限，没有借显示更新重读文件、刷新事件时间或开始历史清理。真实时间线调度和能耗由 V007 / V011 验证；磁盘年龄 / 容量仍通过既有 [历史清理预览](inbox-maintenance.md)处理。

## 保存格式与失败保留

`AppPreferencesCodec` 使用 kind `tide-island-preferences`、version 1 的 JSON envelope，最大 16 KiB；只编码提醒种类 / 声音 / 安静时段 / 显示名、显示期限与最后一次登录启动意图，不包含会话、位置、正文、凭据或环境变量。

缺少配置采用默认值。未知版本、损坏、超限、未知显示期限或非法安静时段使 `AppPreferenceDocument` 进入只读状态；原生保持原 UserDefaults 值，普通控件编辑不能覆盖。读取失败时提醒关闭、项目名隐藏、历史显示取 1 小时。只有明确点击“恢复显示与提醒默认值”才允许替换记录，重置保留系统当前登录启动状态。

原生把整个编码 Data 保存在当前应用域的 `tide-island.preferences.v1` 键，不使用 Codex 配置文件或 inbox checkpoint。UserDefaults 接收写入不等于本轮已验证跨重启持久化；原生恢复和系统行为由 V009 验证。配置 version 1 是本项目格式，不改事件 v1 / v2 或会话 checkpoint v2。

## 项目名与活动顺序

显示名选项与快照 / scope / sourceSequence 一起提交调度器，迟到输入不能恢复旧选项；选项变化强制协调，最新 pending 仍合并。控制器及调度器均使用相同的偏好投影，保留原时间 / 最早截止 / 数量 / sessionURL；先校验来源内容，再替换显示名称，不能借隐藏掩盖非法元数据。

显示名隐藏后源项目名不进入新 Activity ContentState，通知也在权限 await 后重新取最新显示名设置。已分派的系统操作先返回，再应用最新 pending；这不承诺撤销已经出现的系统内容。

系统关闭记忆比较 sessionID、phase、计数与原观察时间，忽略显示名差异。因此改显示名不会重新创建刚关闭的同一观察；新的真实观察 / 聚合状态仍可恢复。规则与 [活动生命周期](activity-lifecycle.md)一致。

## 权限与系统操作

初始化只加载配置、查询登录项实际状态并连接来源；不申请通知权限，不因保存的 launchAtLogin 意图自动注册系统服务。

开启提醒是明确用户动作：请求 alert / sound 权限，允许才将 enabled 保存为 true；拒绝和请求异常提供不同固定提示。等待期间其余设置可编辑，返回后仅合并 enabled 字段，保留最新声音 / 名称等选择。重置会使正在等待的权限操作失效，晚返回的允许结果不能再次开启提醒；退出也隔离晚回调。

登录启动使用公开 `SMAppService.mainApp`；查询状态、注册 / 注销与需要系统批准分别表达。requiresApproval 显示待允许并提供公开的登录项设置入口；操作失败重新查询实际状态，保留固定错误，不保存 SDK 异常正文。注册过程中其余设置的编辑在完成后保留。保存的意图不会覆盖用户在系统设置中的实际选择；唤醒 / 激活重新查询状态。

T023 的 [系统状态](system-status.md)区域独立显示活动授权、通知权限与登录批准。读取权限不会发起授权或注册登录项，晚查询用代次隔离；系统重查入口放在只读表单之外，损坏偏好时仍可恢复通道和检查能力。

没有调用私有系统设置 URL、修改 launch agent 文件或在开发机实际注册登录项。通知 / 登录相关操作在此轮只编写源码，共享测试全部使用合成客户端。

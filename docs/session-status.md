# 会话存活、状态新鲜度与过期

T007 在轮次状态机之外提供 `SessionStore`、`SessionStatusPolicy` 与 `SessionSnapshot`。事件记录“观察到了什么”，时间投影决定“现在能展示到什么程度”。投影使用调用方提供的 `now`，不改写事件、turn、UUID 或原始 phase。

## 状态与时间规则

当前 Codex hook / notify 没有心跳、进程实例身份或可靠存活查询。近期工作记录只代表近期观察；本轮结束也不能证明进程仍在运行或已经退出。不通过扫描进程、工具名称、聊天内容或没有新事件的时长猜测退出。

| 原始 phase | 记录未满 5 分钟 | 5 分钟及以后 | 展示保留 |
| --- | --- | --- | --- |
| `working` | 工作中 | 状态待确认，保留“最近记录：正在工作” | 不因无更新自动隐藏 |
| `needsInput` | 待处理 | 状态待确认，保留最近的待处理记录 | 不因无更新自动隐藏 |
| `completed` / `failed` / `interrupted` | 本轮已空闲，保留具体结束 / 异常 / 中断说明 | 历史状态 | 从事件时间起 24 小时 |
| `ended` | 明确的会话结束记录 | 历史退出记录 | 从事件时间起 1 小时 |

边界采用 `now < freshUntil` 与 `now < expiresAt`：到达 5 分钟时即不再新鲜，到达保留期限时即退出可见列表。`idle` 只描述本轮状态，不承诺 Codex 进程空闲或存活。

`SessionFreshness` 分为 `fresh`、`stale`、`expired`、`clockSkew`。事件时间晚于当前时钟或时间差无法计算时，状态为待确认，不进入实时工作 / 待处理计数，也不为异常时间安排无界等待；后续新事件、应用激活或睡眠唤醒时重新判断。

新鲜度和保留期限一律基于标准化事件的 `occurredAt`，不使用文件修改时间、读取时间或重新启动时间。带源时间的事件不会因为 `context.receivedAt` 更晚而变新；当前固定 Codex 适配器仍以首次 bridge 接收时间填充 `occurredAt`。受来源限制，bridge 很晚才收到的上游观察无法精确还原真实执行时刻，见 [事件契约](codex-events.md)。

T013 为可选 Wave 位置增加独立的时间 / 来源投影，位置过期不改变本节生命周期和计数；到期截止时间合入一次性投影通知，见 [位置有效性](wave-location.md)。

## 恢复与过期的边界

应用通过共享 `SessionStore.receive` 处理 inbox 的有界批次，移除原先“只接收最近 15 分钟事件”的过滤。批次内两小时前的工作或待处理记录可以恢复为状态待确认，不会被宣称为实时工作，也不会仅因这个时间窗口消失。

重复读取同一批次不会更新事件时间。过期只影响投影，不从 registry 删除会话、轮次保护或去重历史；重复历史、同轮迟到工具不能借助展示过期重新打开终态，明确的新轮开始仍可恢复正常状态。当前进程已接收的未结束会话不会因之后被其他会话的 inbox 文件挤出最近集合而丢失。

T009 已改为首次导入全部有界合法候选，默认最多 16,384 个文件，不再截断为最近 256 个；超限时整体拒绝，不返回不完整启动批次。后续只读取新增 / 变化正文，显式清理完整保留未结束历史链，见 [inbox 维护](inbox-maintenance.md)。游标正文不跨重启复用，T011 checkpoint 保存会话、轮次窗口和导入摘要；重启重新扫描来源。已保存终态在文件清理后仍有保护，缺少源边界或从未保存的历史无法凭空重建，见 [会话持久化](session-persistence.md)。展示过期本身不删除文件，也不是内存 / 磁盘容量上限。

T010 在时间规则之外增加通道确认：读取失败或有损坏 / 未知协议时保留观察但暂停实时计数；当前目录缺失或改写了展示事件时，旧记录保持待确认。通道恢复不会改写时间、轮次或偏好，必须再次确认同一观察或接收新的有效状态。具体规则见 [通道故障恢复](inbox-recovery.md)。

## 列表、计数与原生源码

T008 在时间投影之外加入已读、忽略、置顶和选择偏好。新鲜待处理始终优先；已读的完成提醒退出高优先级，置顶和选择可影响列表位置，但不改变活动 / 新鲜度。完整排序、忽略后的恢复和选择回退见 [会话注意力规则](session-attention.md)。

只有未被忽略、通道及当前观察已确认且新鲜的 `working` / `needsInput` 进入实时计数和 Activity 候选，历史完成状态不会因重启而创建新的实时活动。聚合 `activityStaleAt` 取所有参与计数会话中最早的新鲜度截止时间，避免选中会话较新时让另一条旧状态继续算作实时。已忽略记录自身的时间边界仍用于刷新恢复列表。

原生源码已接入相同投影：

- 列表显示待确认状态及最近观察，过期历史退出可见列表。
- 共享接收器的单次定时任务在下一次新鲜度 / 保留期限边界发布新帧，只计算内存状态，不轮询进程或定时扫描磁盘。无后续边界时不运行计时任务。
- 应用激活和睡眠唤醒时重新读取有界 inbox 并计算当前状态，避免只等待下一次目录变更。
- Activity 使用事件推导的聚合截止时间，不把每次展示更新当作新的 5 分钟。没有新鲜的工作 / 待处理状态时结束活动；原先结束状态的 30 秒展示留待 T018 完整生命周期设计。
- 应用挂起时依赖系统 stale 标记，把岛上的状态和计数改为待确认，避免继续显示旧的工作数量。

这些接入已随最新 beta 原生 Debug / Release 编译通过，见 [当前进度](development-progress.md)。共享接收器单次到期已加入实际帧发布测试；原生订阅时序、睡眠恢复、系统 stale 行为及布局仍待实机验收，beta 实测和正式环境复验分别记录，不能用共享层测试或工程结构检查代替。

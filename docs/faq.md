# 常见问题

以下答案以当前源码与共享检查为准；原生交互及真实接入的验收状态统一见 [开发进度](development-progress.md)。

## 现在能安装使用了吗？

尚未公开发布下载版本。本机开发包已完成 27.3 beta 原生双配置编译、ad hoc 签名安装，用户实机截图确认原生岛布局，真实开始 / 工具 / 完成回调已有观察；其他交互与正式环境仍分别验收。实际包和验证边界见 [开发进度](development-progress.md)。

## 有灵动岛硬件，为什么还要等系统？

本项目原生 target 使用 macOS / SDK 27.3+ 公开接口，硬件存在不能替代系统接口可用性。目前 beta 编译与本机展示已有证据，正式环境仍需复验；标准 Intel CI 仅验证共享层。支持版本与硬件边界见 [兼容清单](compatibility.md)。

## 什么时候会出现或收起？

潮汐岛保持运行、系统允许实时活动，并有来源已确认、未忽略且仍新鲜的“工作中 / 待处理”会话时，会向系统申请创建或更新活动。新任务开始、工具事件及权限请求等已接入信号会推动状态变化；待处理优先，其次是当前选择或其他工作会话。某个会话结束但其他会话仍在工作时，岛继续显示。

每个会话以最近事件计算 5 分钟新鲜度；没有新事件或来源异常时停止确认其为实时工作。全部没有符合条件的会话时请求结束活动，正常退出应用也会清理。系统主动关闭的相同观察不会立即反复重建；新观察可以重新协调。活动已创建不表示始终显示展开的大卡片，实际展示样式与时机由系统决定。

当前本机已验证的限制是：通过现有入口新建活动需要潮汐岛在前台，已有活动可以后台更新。一直停留在 Wave 时，新任务未必能自动起岛；可打开潮汐岛会话窗口，必要时重新检查系统状态。这与独立的通知提醒开关无关，不需要为此启用完成通知。公开前台要求见 [Apple Activity 文档](https://developer.apple.com/documentation/activitykit/activity)。

## 为什么工作一段时间后显示“状态待确认”？

共享层默认新鲜度为 5 分钟。长时间没有新观察、当前文件缺失、通道异常或时钟倒退时，保留最近记录并暂停实时判断；不会通过检查进程存在来伪造工作状态。先查看通道原因与原时间，确认新事件能进入，再使用明确的恢复入口。规则见 [会话状态](session-status.md)。

## 普通提问、工具失败和“本轮结束”分别怎么处理？

`PermissionRequest` 表示许可请求；普通问题是否真的阻塞等待，现有 hooks / notify 无足够语义。工具失败可以恢复，不能代表整轮失败；Stop 可能被其他 hook 续跑，不能代表结束。本轮结束只来自完成 notify，仍应返回终端确认结果。T031 的 [公开 app-server 研究](app-server-research.md)已找到结构化候选，但无干扰来源尚未验证，当前没有启用适配器，也不从工具名或聊天正文猜测。

## 配置安装成功了，为什么没有会话？

安装工具只操作显式目录中的 `hooks.json` 与 `config.toml`；Codex 配置层、信任及重载状态需另行确认。核对目录是否实际生效、`/hooks` 是否信任、新事件是否写到应用默认 inbox，以及 notify 是否正常回调。应用不会跟随 CLI 自定义 inbox。不要为了排查复制完整环境 / 聊天 / 配置正文到诊断；先用 [必要元数据报告](diagnostics.md)区分版本清单与实时来源状态。

## 会覆盖我已有的 notify 或其他 hooks 吗？

统一接入只维护自身六类 hooks 和顶层 notify wrapper。原 notifier 的参数留在同一设置内，由 wrapper 在观察后转发原 JSON；卸载恢复原参数或原本缺省状态。其他 hooks、TOML 字段和信任记录保留。编辑器遇到不支持 / 不明确的 notify 格式会拒绝，不强行重写配置，详见 [notify 共存](notify-integration.md)。

## 返回 Wave 为什么没有跳到那个分屏？

首版原生源码只实现固定 bundle 的应用打开请求。已审阅 Wave 0.14.5 `focusblock` 是依赖认证与 tab 的标签内布局聚焦；当前没有真实 focus driver，也没有公开稳定的跨标签 / 窗口路线。诊断里的 application / focus 请求或响应不证明目标会话可见。请在 Wave 确认会话，见 [Wave 能力](wave-capabilities.md)。

## 为什么开启提醒后，没有补发旧的完成通知？

启动时建立基线；已读、忽略、安静时段或关闭提醒会消费相应周期，之后不补发。系统通知权限与实时活动独立，系统也可能调整横幅 / 声音。提交失败可能已经送达，同周期不会自动重发。项目筛选、打开详情和返回 Wave 本身不会当作“已经在看该 block”，见 [提醒规则](session-reminders.md)。

## 如何关闭项目名称，或者恢复损坏设置？

在「设置 → 显示」关闭项目名称，作用于列表、实时活动与通知；不会改事件中的原始元数据或返回身份。损坏 / 未知格式的设置保留原键并阻止普通编辑，可明确点击「恢复显示与提醒默认值」。它不清除事件、会话偏好或注销登录项。详情见 [偏好设置](preferences.md)。

## 清除状态后，离线诊断为什么仍能看到事件文件？

会话清除会保存空状态与旧文件导入边界，保留事件；离线诊断只数磁盘文件，不读取 checkpoint 或重建当前会话。因此文件仍在并不表示旧会话复活。历史显示期限也只影响界面。删除 checkpoint 会丢失抑制边界，不能拿它代替清除操作，见 [迁移规则](migrations.md)。

## 安装只完成了一部分，或者应用移动后怎么办？

按报告的 completed_steps、failed_step 与固定 failure_code 核对；解除锁忙等原因后重新预览当前状态，再应用新的总指纹。移动或升级后使用新应用包的 helper 与 `--app` 路径重新预览。各文件独立备份与发布，没有跨文件事务；不要盲目把旧备份覆盖并发编辑。操作见 [安装与恢复](installation.md)。

## 导出诊断会包含什么，为什么保存失败？

报告最多 16 KiB，只含版本、来源 / 持久化 / 系统固定码、汇总数量、时间与单次真实返回路线；不含会话 / 事件 / 工具 / 位置身份、项目名、聊天、路径或凭据，不自动上传。应用使用当前缓存，CLI 默认只报版本、显式 inbox 才做离线清单。保存需已有可写目录中的新文件，并在受保护数据根之外；现有文件或链接不会被覆盖。详细范围见 [诊断](diagnostics.md)。

## 如何完整停止接入并卸载？

先关闭应用登录启动并退出；在移除包内 helper 前预览 / 应用 `integration uninstall`，恢复原 notify 并删除自身 hooks，再移除应用包。默认保留事件、checkpoint 和显示 / 提醒设置；明确 `--data clear-state` 只清会话状态与会话偏好，事件和独立设置仍保留。当前没有一键删除全部用户数据的命令，安装器也不删除 Codex 聊天或项目文件。步骤及数据表见 [卸载说明](installation.md#卸载与数据选择)。

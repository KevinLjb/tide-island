# 事件通道故障恢复

T010 把通道健康、目录监听、接收锁、有界重试及中断操作恢复放到共享 `InboxReceiver`，让原生列表和实时活动使用同一份状态投影。

## 状态确认

`healthy`、`recovering`、`degraded`、`unavailable` 和 `stopped` 描述通道，与原事件 phase、时间新鲜度分别保存。读取失败、监听丢失、损坏 / 未知版本 / 超大 / ID 不符事件、不安全文件或未完成操作都会暂停实时计数；已有工作 / 待处理显示“状态待确认”，保留原时间、轮次、已读和置顶。

成功读取不等于所有旧状态都已恢复。只有当前目录中仍有与展示观察一致的合法事件，才允许其参与实时计数；目录重建为空、单个文件移除或同 UUID 被外部改写，不会让内存旧状态重新变活跃。新鲜度和未来时钟限制继续独立生效。正常重读不会延长五分钟新鲜期。

`InboxUpdate.rejectionCounts` 区分 malformed、unsupportedVersion、oversized 和 filenameMismatch。损坏文件保持原样，不把正文拼入日志或诊断。默认采取保守策略：目录中存在无法解释的候选事件时，整个通道暂停实时计数，避免遗漏的终态使其他旧状态继续显示工作。

## 监听与单接收者

接收器使用目录描述符监听 write、delete、rename、revoke、attrib；同时监听父目录，以便事件目录重建后重新连接。新监听器使用递增代次，已取消监听器排队的旧回调不能使新通道失效。写入突发合并约 30 ms；每个接收器串行完成 IO、操作和快照发布，流只缓冲最新帧。时间过期使用一次性计时任务，没有后台轮询。

父目录中的 `.tide-island-receiver-<摘要>.lock` 是空的持久锁文件，摘要来自目录槽名称，不包含会话正文。内核 flock 限制同一目录的独立接收者；Events 删除不释放该锁。stop / 进程退出释放内核锁，空文件保留。大小写折叠会保守地将同父目录下仅大小写不同的名称视为同一槽。父路径 / 锁文件被替换时重新验证并停止使用旧锁。

启动幂等；显式重新连接、激活和唤醒都会复核路径并重新监听。busy、目录暂时不可用、读取竞争和 IO 故障最多自动重试五次，间隔约 0.1、0.2、0.4、0.8、1.6 秒。预算耗尽后等新的文件系统信号或显式重连；无效标记、资源超限和第二接收者直接给出诊断，不无限轮询。原生源码提供“重新连接”入口。

## 中断写入

写入者在协作排他锁内写 `.tide-island-<UUID>.tmp`，完整同步后链接为事件 UUID 文件。恢复同样持锁，仅接受当前用户所有、大小有界、可解码验证的普通暂存文件：

- 完整暂存且目标不存在：按原 UUID / 时间发布，不重新生成事件。
- 已发布目标与暂存为同一个 inode（两条硬链接）：删除多余暂存链接，恢复单链接事件。
- 不同 inode 但目标内容完全相同：仅移除重复暂存。
- 部分 JSON、未知版本、过大、符号链接、其他硬链接或同 UUID 内容冲突：保留文件并报告原因码。

## 中断清理

用户按 fingerprint 批准清理后，在首个删除前发布 `.tide-island-cleanup.json`，仅记录版本、目录 / 标记身份、批准指纹、UUID 文件名、文件属性及内容摘要，不保存事件正文。恢复不重新计算或扩大删除集合：已缺失条目视为已完成，仍在原处且属性 / 摘要一致的条目继续删除。

发现任意替换、改写、链接或目录身份冲突时，保留剩余文件和日志，阻止导入不完整历史，也不删除其他尚未完成条目。修复冲突后重试；需要人工保留的冲突文件可先移到 inbox 外，再恢复剩余已批准操作。写入者也先完成既有清理，避免新写入与残缺历史交错。没有用户批准的新历史清理不会自动开始。

这提供进程中断后的保守恢复，不是跨文件事务或断电一致性保证。底层 unlink 与不参与锁的外部编辑器之间仍没有内容比较交换；不要并发用其他工具改写同一目录。未发布的标记 / 清理日志草稿不代表已经开始删除，可能保留在目录中，恢复不会根据这些草稿执行清理。

## 命令行诊断

```bash
# 默认预览；目录和标记必须已存在，不创建或清理用户文件
swift run tide-island-bridge inbox recover --inbox /absolute/path/to/TideIsland/Events

# 完成此前已开始的写入 / 已批准的清理，无新增清理授权
swift run tide-island-bridge inbox recover --inbox /absolute/path/to/TideIsland/Events --apply
```

`--scan-limit` 和 `--read-budget-bytes` 沿用 [inbox 维护](inbox-maintenance.md) 的上限。恢复日志自身最多 32 MiB；日志及核验正文、暂存正文均有读取预算。输出只有操作数量、TideIsland 文件名与原因码；应用有未解决项时 mode 为 partial，退出码非零。原生接收器自动完成同样的既有操作，无法安全恢复时暂停实时状态并保留诊断。

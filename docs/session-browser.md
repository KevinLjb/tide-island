# 会话浏览与详情

T022 使用共享 `SessionBrowserProjection` 计算项目选项、列表、计数和空状态，原生接入项目筛选与只读详情。筛选和检查不修改会话状态或已读，明确操作继续绑定用户看到的完整引用。

## 按项目查看

先按 [显示偏好](preferences.md)处理历史可见性，再将项目名称分组。项目选择只过滤列表，岛上候选仍沿用全局注意力 / 当前选择，不因浏览另一项目而自动切换。

组 ID 由带类型域的 SHA256 生成，名称先做 Unicode NFC 规范化；等价组合字符进入同一组，大小写不同的名称保留区分。名称组描述相同显示名称，不通过名字推断目录、workspace 或认证连接。

显示项目名时使用原名称；隐藏时显示“项目 1”等匿名选项，筛选 ID 保持相同。行与详情显示有界的稳定会话标签，标签不暴露原 sessionID / 路径，也不代替操作所用的完整 SessionReference。隐藏 / 筛选不重写源名称、观察时间或会话引用。

计数只对应当前项目内可见的普通记录：未读与新鲜待处理分别计算，已忽略记录不计入；“显示已忽略”只控制检查入口，不恢复观察。各组同时记录普通 / 已忽略数量，保留只含忽略状态的项目，帮助用户找到恢复入口。

## 实时刷新与窗口布局

会话窗口采用深色底和紧凑卡片：项目名为主标题，状态在同行右侧，说明与匿名会话标签 / 原观察时间为次级文字。新鲜工作为蓝色，待处理和异常为橙色，未确认与已结束保持中性；选中态以细描边和选择符号同时标识。状态不会只通过颜色传达。

每张卡片保留直接返回 Wave 的 44 点点击区域；详情、选择、已读 / 未读、置顶、忽略 / 恢复收进会话操作菜单。详情读取、完整引用校验与动作保持原有流程。长项目名为单行中间省略并保留完整 help / 读屏内容，说明行预留一行，避免状态说明出现时撑高卡片。

选择摘要、活动候选和底部提示各自保留稳定区域：选择 / 候选为单行，底部消息预留两行，重连按钮保留布局位置、仅在需要时显示并可用。长提示可悬停查看全文，读屏仍使用完整消息；没有消息和不可用的按钮不进入无障碍导航。正常刷新、来源重确认及返回 Wave 的提示变化不会增删这些外层区域。会话列表 / 空状态占用剩余空间，列表更新不播放布局动画。

默认窗口为 480 × 560 点，最小内容高度为 480 点，避免较矮窗口只露出会话行上半部。用户手动展开系统状态或调整窗口大小仍会改变可用空间。模型保留每帧诊断与真实来源状态，但不重复发布相同操作提示、恢复标记或快照；活动的强制同步仍继续执行。列表排序、当前引用校验、过期策略与岛上候选优先级没有改变。

## 空状态

| 情况 | 界面动作 |
| --- | --- |
| 尚无记录 | 等待开发会话，管理菜单保留演示入口 |
| 较早已解决状态被显示时长隐藏 | 显示说明与设置入口，源数据保留 |
| 当前项目已不可用 | 保留明确筛选状态，可点击显示全部项目 |
| 当前项目仅有已忽略记录 | 可展开检查 / 恢复，不自动恢复 |
| 时间无法确认 | 明确提示检查时间及重新连接 |
| 通道或保存需要恢复 | 持续状态提示与重新连接入口保持可达 |

项目消失不静默切换为全部；Picker 保留失效选项的说明，恢复动作由用户明确选择。未确认的工作 / 待处理在历史显示期限外仍保留，不将它们当作结束记录移除。

## 详情与最近观察

“详情”打开原生 sheet，绑定打开时的 SessionReference；读取 [最近元数据](session-metadata-history.md)默认 8 条，只显示 source / kind / phase / 原时间及当前观察标记。后台查询只用现有缓存，不重新读取文件。来源确认时间来自接收器的最近成功扫描，不是打开 sheet 的时钟。

源观察变更 / 被移除 / 不再显示时，旧详情停止提供原操作，显示变化提示；用户点击“查看当前状态”后才采用新的引用。当前状态卡片与历史观察分别展示，退役 / 迟到观察不当作已应用或最新状态。

元数据加载绑定引用与请求代次，后到的旧请求不能覆盖新读取，关闭 / 引用变化也隔离晚结果。历史默认在打开时读取，可通过“重新读取观察”检查新的已确认缓存；来源中断时提供固定原因及重新连接，不将读取作为恢复 / 清理或已读动作。

选择会话、返回 Wave、标记已读 / 未读、置顶 / 取消置顶、忽略 / 恢复均继续调用既有引用校验；打开详情和改变筛选不会自动标为已读，也不能当作正在查看 Wave 同一 block 的可靠证据。

管理菜单集中放置设置、演示、历史清理预览 / 已预览应用以及会话 / 偏好清除。清除仍使用已有预览 fingerprint 和确认内容；浏览 / 历史读取不开始新的清理。

## 验证范围

新增 14 项共享测试覆盖空快照、项目分组 / 普通与忽略计数、过滤顺序与原引用、隐藏名称、Unicode 规范等价与大小写、失效筛选、忽略检查、历史隐藏、未确认状态、全局选择不变、非法时钟、来源中断的待处理计数与稳定匿名标签。元数据接口的 15 项共享测试保留。

原生工程共有十个 Swift 文件，详情和窗口布局辅助视图放在既有 SessionListView.swift 内。模型的查询后最新引用 / 主来源检查及 SwiftUI 请求代次保留，实际 sheet 生命周期、Picker、菜单 / 确认框、键盘 / 触摸、长名称及性能继续分别验收。窗口区域可在隔离的 NSHostingView 中比较空提示、选择、重确认、返回及长错误的布局；该组件测量不等于真实用户窗口已确认不抖动。实际共享 CI、原生编译和安装结果见 [开发进度](development-progress.md)。

2026-11-18 的 build 7 卡片在 388 / 448 点宽度分别渲染工作、待处理、本轮结束及来源待确认状态，说明行和卡片高度保持一致；20 组选择 / 候选 / 提示辅助组件布局预算测量通过。辅助组件测量只覆盖其布局契约，完整窗口的系统菜单、持续刷新及实际输入仍单独核对。

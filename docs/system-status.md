# 系统能力、授权与错误

T023 的 `SystemStatusProjection` 将实时活动、通知和登录启动分开呈现，原生会话窗口、设置及菜单栏使用同一投影。状态仅消费公开 API 的结果和已有交付错误，不从机型、进程存在或请求成功推断岛上已经显示。

## 能力与来源

实时活动区分未检查、接口不可用、系统关闭和系统允许。系统允许时仍需健康的主接收器确认事件来源；展示位置、显示时机及硬件适配由系统决定。无新鲜会话时不会为了能力检查而创建活动。

通知有独立的未检查 / 未申请 / 允许 / 拒绝状态。应用自己的提醒开关关闭时显示关闭，读取系统权限不触发授权或通知。允许也不证明横幅 / 声音已显示，仍遵守 [提醒周期与抑制](session-reminders.md)。登录启动继续以 ServiceManagement 返回状态为准，等待批准不会显示为已启用。

当前应用最低系统仍为 27.3；接口不可用分支为防御性展示，不代表安装包支持在更早系统启动。没有使用私有硬件检测或自绘浮层来补足原生能力。

## 错误与恢复

能力和上次交付错误分别保留。例如系统重新允许活动，但上次更新尚未确认时，仍显示上次失败；下次有序同步成功后才清除该错误。不同领域的问题可同时查看，不再由一个通用错误遮住其他错误。

| 情况 | 提示与处理 |
| --- | --- |
| 系统关闭实时活动 | 检查系统设置；菜单栏和会话列表继续可用 |
| 来源不明 / 非主接收器 | 等待事件通道恢复，不宣称实时状态可信 |
| 活动创建 / 更新失败 | 分别提示；可能保留旧状态，允许重新检查 |
| 活动清单 / ID 无法确认 | 保留无法确认的活动，不以清空或新建掩盖问题 |
| 结束未确认 | 即使系统关闭活动，也保留清理失败提示 |
| 通知未申请 / 拒绝 | 前往应用提醒设置，由用户主动完成授权 |
| 通知提交结果不明 | 说明可能已提交，同一周期不自动重发 |
| 登录启动待批准 | 使用公开系统登录项设置入口 |

“重新检查系统状态”只查询公开权限 / 登录项并通过接收器重连、来源序号和原有调度强制协调。它不重放旧提醒，不解除系统关闭记忆，不安装配置，不注册登录项，不修改已读或观察时间。系统活动失败不会移除菜单栏入口或会话操作。

启动、激活、唤醒、活动授权 / 状态信号及主动授权结束后查询系统状态；没有轮询硬件或高频查询权限。通知权限读取使用请求代次与取消 / 退出检查，迟到结果不能覆盖新查询。恢复入口放在只读偏好表单之外，损坏配置时仍可使用。

## 验证范围

共享测试覆盖独立权限、来源未确认、关闭与清理失败并存、错误恢复、通知不确定结果、多个同时问题和登录批准语义。工程检查只核对原生文件成员与配置。

公开 API 的正式签名、原生编译、系统权限变化、菜单栏及窗口布局、读取回调和登录项操作继续由 [27.3 统一验收](development-progress.md#6-macos-273-正式环境统一验收)执行。本轮没有执行真实权限请求、通知、登录注册、Wave 操作或 hooks 安装。

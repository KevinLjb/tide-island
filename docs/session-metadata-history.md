# 会话最近元数据

T022 的读取接口在应用内返回最近观察的必要字段，使用接收器已确认的缓存和既有记忆窗口；查询本身没有文件读取、事件重放、已读 / 选择动作或清理操作。T022 的 [列表 / 详情](session-browser.md)已通过此接口接入，原生继续待 27.3 验证。

## 当前观察与来源

`InboxReceiver.metadataHistory(for:limit:)` 要求接收器已启动且来源健康，调用者提供当前可见 / 已忽略的完整 SessionReference。观察被新事件替换、展示到期或会话不存在时返回 staleSelection；来源中断、记录缺失或损坏时返回 sourceUnavailable。无效时间与不合法数量有单独固定错误，均不回显原输入。

权限为只读：已忽略状态可以检查，读取不恢复它，也不将未读改为已读。结果携带最近一次成功扫描的 confirmedAt，不将查询时钟冒充新来源确认，不推断提供方进程仍在运行。

## 清除和重启边界

可查询 ID 来自该会话已有的 512 UUID 记忆窗口，加上当前观察作为只读锚点。锚点即使已被 FIFO 淘汰也可展示，但不会重新插入去重窗口、改变下一淘汰位置或扩大重复事件保证。

最终候选必须同时存在于接收器当前已确认的事件缓存，并属于该会话的上述 ID 集合。checkpoint 已保存的窗口在重启后仍能检查；主动清除后只有新会话状态记住的新 ID 可以查询，因此保留在磁盘上的旧文件不会因同一 sessionID 继续工作而重新出现在历史中。规则沿用 [会话持久化](session-persistence.md)的导入抑制边界。

不新增 checkpoint 字段或版本。接口只读取现有 registry / store / receiver 状态，事件协议仍为 v1 / v2，checkpoint 仍为 v2。

## 结果与含义

默认 8 条，最多 20 条；0、负数及超限返回错误。排序仅处理最多 513 个匹配缓存记录，按原 occurredAt 倒序；同时间优先当前观察，再按 UUID 稳定排序。availableCount 是当前缓存与记忆窗口内可用数量，清理 / 淘汰后的记录不在此范围。

每条 `SessionEventMetadata` 只含 UUID、phase、原 occurredAt、可选 source / kind、是否当前观察。项目名、Wave 位置、turn / 工具身份与名称、聊天正文、认证及环境均不进入该展示 DTO。v1 没有来源信息，显示“未记录来源”。

记忆窗口也含被 registry 忽略的迟到 / 退役观察。历史只展示观察，不把每条都当作已应用状态，不以倒序排列推断因果或成功。当前状态仍由 SessionSnapshot / 当前引用决定；“工具结束”“本轮结束”标签不增加任务成功含义。

## 验证与接入

新增 15 项共享测试覆盖按会话隔离、必要字段 / 隐私、v1 未知来源、旧引用拒绝、原时间 / 确认时钟 / 已读保持、默认与最大数量、同时间排序、退役观察、checkpoint 重启、清除后的持续抑制、当前文件缺失、停止 / 非法时钟、已忽略状态、来源损坏 / 展示到期，以及 FIFO 锚点不扩大去重窗口。

测试只使用隔离 inbox、合成事件与受控时钟。项目筛选和详情界面通过 [会话浏览](session-browser.md)接入；实际共享证据见 [开发进度](development-progress.md)，原生输入、显示和性能继续单独验收。

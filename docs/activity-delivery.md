# 实时活动更新调度

T017 将最新状态合并、去重、节流与结果通知移到共享 `IslandActivityScheduler`；它独占一个 [基本活动控制器](activity-presentation.md)，原生界面提交快照并订阅客户端响应，不在 UI 内重复编排 SDK 操作。

## 来源顺序与合并

每个调度器接收单一有序来源，调用者提交 `SessionSnapshot` 和单调递增的 UInt64 sequence。源端在产生快照时分配序号；调度器拒绝小于或等于最近已接受序号的调用。晚执行的旧 Task 不会因更晚到达而变成“最新”。序号不替代事件时间、turn 因果或进程存活证据，来源重建须使用新的调度器。

内存仅保留一个最新 pending 快照。已有 SDK 操作执行期间，新的快照替换 pending；当前操作返回后只处理最新一个。调度器独占基本控制器，request / update / end 不重叠；已发出的操作无法撤销，也不保证系统瞬间显示最终状态。

`submit` 返回是否接受入队，不表示 SDK 已接收或系统已显示。调用者取消提交 Task 不撤销已接受的来源状态；关停、退出和系统活动协调由 T018 处理。`flush` 只等待当前队列稳定，供验证使用，不轮询或伪造响应。

## 去重与失败

去重比较完整展示 state 和 staleAt，不比较整个会话快照。偏好、位置有效性或新事件 UUID 变化但展示完全相同时，不再调用 SDK。相同 state 但源截止时间更新时仍须更新，不能延长或丢失真实期限。

去重缓存来自基本控制器实际返回的、授权查询后的投影；不能缓存授权 await 前已经过期的候选。空展示成功后记录为空，避免后续空快照重复查询授权或结束。

发起生命周期操作前将旧去重缓存标为未确认。未知失败可能已改变系统状态，下一次明确来源输入不能仅凭旧成功缓存跳过操作；例如更新可能已经应用后才丢失响应，之后回到旧展示也必须重新发送。失败不自动循环重试，更不创建另一个活动来掩盖 update 失败。新的有效快照可再次尝试，错误在成功或等价同步后清除。

## 限频与紧急更新

普通非空变化采用 **1 秒开发间隔**，按单调 uptime 计算，不使用可能回拨的墙上时间作限频时钟。墙上时间仍独立用于展示有效期。无效 / 回退的单调时钟产生固定错误，不安排无界等待。

等待期间新的普通快照仅替换 pending；等待结束后重新选择最新快照、重新投影时间和截止，不发送早先捕获的负载。待处理数量增加、待处理高亮目标切换，以及空展示 / 失去确认可以打断限频等待；重复待处理观察仍可合并限频。已经执行的 SDK 调用先完成，随后应用最新状态。

等待任务独立于 SDK 工作任务，紧急状态取消的是等待，不借此并行操作 SDK。等待异常时报告 schedulingFailed 并停止当前批次，后续新输入可以恢复；不进行后台无限重试。计时器为一次性任务，没有固定轮询。

1 秒不是已验证的系统限额或能耗结论。展示内容继续遵守共享 JSON 3 KiB 开发预算，正式 SDK 的真实序列化 / 传输上限和性能由 V001 / V011 核对；本轮不把这些开发约束标为正式 SDK 验收通过。

## 响应流

调度器对单个订阅者发布 `IslandActivityDelivery`，缓冲最新一帧：

| 字段 | 含义 |
| --- | --- |
| sourceSequence | 最近已接受的来源序号 |
| synchronizedSequence | 最近经客户端返回或相同展示去重后确认等价的来源序号 |
| phase | idle、scheduled、updating、synchronized、failed |
| problem | 最后未恢复的固定错误；不携带 SDK 异常正文、凭据或会话正文 |

新输入等待期间保留上一次错误，成功或等价同步后清除。序号和 synchronized 只描述共享控制与客户端调用返回，不证明 OS 窗口可见、系统已渲染或原生活动健康；失败后的实际 SDK 状态仍可能未知。

## 原生接入源码

`SessionModel` 在主 actor 为每个不同的共享帧快照分配序号，再提交给 `NativeActivityController` 的调度器。原 UI 中的 pendingSnapshot / 更新循环已移除；延迟到达的提交按来源序号拒绝。独立任务订阅 delivery 流，继续让通道 / 保存错误优先于活动错误和返回 Wave 提示。

原生适配仍只使用公开 ActivityKit / WidgetKit，未新增 Native 源文件或自绘浮层。SDK 客户端实际调用、消息交互、线程隔离和系统效果尚未编译 / 运行，继续待 27.3 正式环境。

## 验证与后续

新增 18 项共享测试使用明确时钟、可控等待及 SDK 替身，覆盖乱序来源、元数据去重、进行中 / 等待中的合并、普通限频、紧急打断、旧聚合到期、授权后真实投影缓存、不确定失败后的重发、新输入恢复、计时器异常、单调时钟回退、空展示、真实响应流以及 1,000 次突发最多一个 pending 的交付行为。原有基本活动控制测试保留。

实际 CI 证据见 [开发进度](development-progress.md)。T018 继续处理创建 / 结束、遗留活动、授权变化、重启和退出；T019 完善系统视图，T020 处理提醒 / 安静时段，均不会把本轮替身测试当作原生验收。

# 会话提醒与安静时段

T020 提供共享提醒协调器及 UserNotifications 接入源码：只提醒新确认的“等待你处理”和“本轮已结束”，不读取聊天正文，不把本轮结束说成任务完成或测试通过。原生默认关闭，T021 提供设置入口和主动权限申请；本轮没有请求本机通知权限或发送真实通知。

## 启动与提醒周期

单个 `SessionReminderCoordinator` 接收有序快照、源端 UInt64 序号、主接收器状态、设置及可选可信查看证据。小于或等于最近序号的调用整体拒绝，不能通过迟到的设置或权威覆盖当前状态。

第一次健康主接收器快照只建立基线，包含其保留的待确认记录，不补发启动历史。第二个非主实例不建立或推进提醒状态，也不发送通知。来源中断后使用新的健康帧恢复判断；活动同步、应用运行或偏好不能代替当前来源确认。

每个会话的 phase 和已知 turn 构成连续提醒周期。同一周期内，即使事件 UUID、项目名、声音设置或快照变化，也只尝试通知一次；工作恢复 / phase 变化，或已确认的 turn 变化才开始新周期。没有工作恢复或 turn 证据时，不凭新 UUID 推断又结束一轮。

协调器最多跟踪 **512 个当前会话**，超限或 ID 重复时整份输入失败，撤销旧输入作为发送依据，不截断或淘汰前缀造成重复提醒。这是共享开发资源边界，独立于 checkpoint 的 2,048 会话上限及系统通知限额。清单中不再展示的会话释放内存记录；重启重新建立基线，不保存正文或永久通知日志。

## 抑制与期限

发送候选必须同时满足：

- 当前健康主来源确认这条观察，仍为 fresh，原始观察不晚于当前时钟且未到 freshUntil。
- phase 为 needsInput 或 completed，对应提醒种类与总开关已启用。
- 当前观察未读且未忽略；选择 / 已读动作沿用现有观察身份规则。
- 当前当地时间不在安静时段，也没有可靠的同一当前会话查看证据。

已读、忽略、关闭提醒、安静时段等抑制都会消费这一周期，不在取消抑制后补发旧提醒。仍可通过应用列表 / Activity 查看当前状态；提醒不自动标为已读，不改写事件、偏好或生命周期。

权限查询是 await，因此返回后重新使用最新快照、设置、声音、原期限和查看证据。已恢复工作、失去主来源、已读 / 忽略、过期或进入安静时段的旧候选不会再提交。传入非法新快照时也不能继续用旧快照发送。

## 安静时段

`SessionQuietHours` 保存一天中的开始 / 结束分钟，范围 0—1439，开始包含、结束不包含；支持跨午夜，例如 22:00—08:00。相同开始 / 结束拒绝，全天关闭使用总开关，不隐式解释等时值。

每次判断使用当前 Calendar 的本地时区和时 / 分，不把一天写成固定 24 小时。夏令时重复小时按相同本地时段处理；时钟无效不发送。没有定时补发或后台轮询，离开安静时段后等待新周期。

## 正在查看会话

只有独立可信 driver 确认 **实际前台 Wave block** 时才可提供 `VerifiedSessionViewing`：必须匹配完整当前 SessionReference、block 和 tab，原位置仍 recent，证据时间有效且窗口最多 5 秒。该时间窗口只是开发边界，不能把普通位置元数据升级成焦点证明。

原生当前没有这样的 driver，始终传 nil。Wave 已打开 / 已激活、列表中选择 / 置顶、位置有效、focusblock 接收请求，都不能单独抑制提醒。已核对的公开路线与局限见 [Wave 能力](wave-capabilities.md)和 [定位结果](wave-navigation.md)。

## 客户端、失败与退出

客户端只查询权限并提交经过校验的元数据提醒，没有隐式申请权限的方法。未申请或被拒绝时返回固定问题码，下一次明确有序输入可以重新查询；不在后台无限重试。原生权限申请方法只留给 T021 的明确用户设置操作，初始化不调用它。

request 使用带 TideIsland 前缀的 SHA256 标识，按会话、周期起点及提醒种类稳定生成；会话 ID 长度参与编码，分隔符不会混淆身份。通知只含固定标题、项目名、声音选项和当前 sessionURL，不包含上下文 / 工具名、输入输出、认证、cwd 或整个环境。

通知提交若抛错，系统可能已接受但丢失响应，因此该周期进入不确定状态，普通输入不自动重新 post。新周期可以再提醒。问题码固定为 deliveryFailed，不传播 SDK 异常正文。成功计数仅表示客户端调用返回，不能证明 banner、声音或通知中心条目已可见。

只有一个权限 / post 操作进行。最新输入可以替换授权等待中的信息；已分派给 SDK 的 post 无法保证撤销，随后恢复工作也不能声称抹掉已出现的 banner。shutdown 立即拒绝新输入，等待已分派操作返回；与 Activity 清理分别启动，两者结束后才停止接收器。已交给系统的通知历史在退出时保留。

## 原生接入与验证

应用使用公开 UNUserNotificationCenter；授权后可注册即时本地通知，前台呈现选项仍服从系统设置。默认点击通过有界 URL 和既有 [会话返回](wave-return.md)处理，重新确认当前会话，不将通知内容拼接为命令；关闭通知不触发返回。

新增 NativeReminderController.swift 已加入应用 Sources，原生文件数为七个。SessionModel 以同一源序号提交活动 / 提醒，健康帧才授予主范围，错误提示仍让通道 / 保存与活动问题优先；退出在释放接收器前等待两个模块停止。

新增 27 项共享测试覆盖启动 / 待确认基线、多会话和周期去重、phase / turn 变化、已读 / 忽略 / 关闭、可信查看及错误证据、跨午夜和夏令时、权限恢复、不确定 post、await 期间失去来源 / 恢复 / 到期 / 安静时段、最新设置、非法输入、容量和退出。全部使用合成通知客户端，不操作真实配置、Wave 或系统通知。实际共享 CI 见 [开发进度](development-progress.md)；原生编译、授权窗口、通知呈现 / 声音 / 点击及系统能耗继续待 27.3。

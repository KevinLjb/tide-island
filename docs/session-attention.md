# 会话已读、忽略、置顶与选择

T008 将用户操作作为 `SessionStore` 内的展示偏好。原始事件、phase、turn、接收时间和新鲜度规则保持独立；置顶、已读或选择均不会证明会话仍在运行。

## 提醒与已读

当前待处理、本轮结束、显式失败和中断状态各有一条注意力记录，对应当前快照的 `lastEventID`。工作中和会话退出不生成未读提醒。失败仍依赖既有显式来源，本功能没有新增自动整轮失败判断。

“标为已读”确认用户看到的这一条记录；“标为未读”可以恢复其未读状态。选择会话或点击“打开 Wave”也确认当前记录已读。打开 Wave 仍只表示尝试应用级唤起，已读或选择不证明精确终端跳转成功。

新请求或新轮次的完成记录使用新的事件身份，重新成为未读；保持选中不会自动读掉新提醒。重复读取、退役轮次或被 registry 丢弃的事件不制造新提醒。权限等待的已读状态不等于权限已处理，因此待处理计数和优先级继续保留。

## 忽略与恢复

“忽略当前状态”只针对当前展示事件：从主要列表、未读统计、实时工作 / 待处理计数和 Activity 候选中移除，放入可展开的“已忽略”列表。选中的记录被忽略时清除选择。

“恢复当前状态”保留原有已读、置顶和事件时间，不会刷新新鲜度。相同事件重读后继续保持忽略；另一条事件被 registry 应用为新状态时自动恢复可见，避免永久屏蔽后续权限请求或新一轮任务。它不是线程级永久静音，也不停止采集或删除文件。

已忽略历史同样按原本期限过期，隐藏列表的新鲜度 / 过期边界仍参与定时刷新。忽略的实时记录不参与聚合 Activity 的 stale 截止计算。

## 置顶、选择与自动回退

置顶按 session 保存，沿用到该会话的新状态和新轮次；取消置顶恢复普通排序。过期记录不因置顶继续显示，过时或未来时间的记录也不会进入实时计数。

选择按 session 保留，明确选择同时将当时的提醒标为已读。选中的会话过时或结束时，Activity 回退到仍有可靠近期观察的候选；过期记录退出可见列表，选择偏好保留，同一会话再次可见时可沿用。点击“自动选择”清除选择偏好，不改变已读、忽略或置顶。

Activity 优先展示新鲜的待处理会话。在这一组内，当前选择优先，其次置顶。没有新鲜待处理时，优先使用选中的新鲜工作会话，再按列表顺序选择新鲜工作。选中的历史 / 待确认记录不会把 Activity 变成实时工作；没有新鲜候选时仍按 T007 结束活动。

## 可解释排序

| 顺序 | 条件 | 展示理由 |
| --- | --- | --- |
| 1 | 新鲜待处理，包含已读的等待 | 待处理优先 |
| 2 | 其他置顶记录 | 已置顶 |
| 3 | 新鲜的未读本轮结束 / 失败 / 中断 | 未读提醒 |
| 4 | 已选择的其他工作 / 待确认记录 | 已选择 |
| 5 | 其他新鲜工作记录 | 当前工作 |
| 6 | 其他待确认记录 | 状态待确认 |
| 7 | 尚未过期的未读历史终态 | 未读历史记录 |
| 8 | 已读终态、退出等历史记录 | 已读或历史记录 |

同组依次按选择、置顶、原 phase 注意力顺序、事件时间降序和 session ID 排序。已忽略记录单独展示，不挤占主列表。排序理由由共享层输出，列表显示同一结果；不会依赖字典迭代、随机 UUID 大小或文件读取顺序。

典型结果：未读完成提醒先于普通工作；标为已读或选择查看后退出高优先级，普通工作排在它前面。选择标记可以保留，在同类历史内优先；主动置顶仍可提高位置。正在等待用户处理的记录始终先于其他置顶和选择。

## 操作一致性与验证范围

`SessionReference` 包含 session ID 和展示事件 ID。`perform(_:for:at:)` 先核对当前记录及过期状态；旧行、新会话、无关 UUID 或过期记录上的操作返回 false，不能将新提醒误标为已读。没有注意力记录的工作 / 退出状态不接受已读操作，已忽略记录须先恢复才能选择或标记已读。

投影、重新读取和时间流逝不会自动标记已读。偏好只保存在当前 `SessionStore` 的内存中，每个操作过的会话保留最新的已读 / 忽略身份、置顶标记，以及一个全局选择。偏好的跨重启保存、清除和内存回收由 T011 继续处理；T009 提供的 [inbox 清理](inbox-maintenance.md)只治理磁盘事件，忽略状态不授权删除未结束历史。

原生列表源码已加入选择、已读 / 未读、置顶、忽略 / 恢复、自动选择、状态理由及当前 Activity 候选说明。共享层测试覆盖状态切换、旧行竞争、自动恢复、过期回退、稳定排序、实时计数和 inbox 字节保留。鼠标、触摸、键盘、无障碍、窄布局及真实 Activity 更新仍待 macOS 27.3 正式环境统一验收。

时间投影见 [会话存活与新鲜度](session-status.md)，事件因果边界见 [会话状态](session-state.md)。真实 hooks 尚未启用。

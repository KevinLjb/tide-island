# 会话与轮次状态规则

T006 在 `SessionRegistry` 中分别维护会话展示快照、当前 turn、已退役 turn、事件去重窗口和工具调用状态。处理只消费已验证的元数据，不读取聊天、进程或原生界面。

## 轮次身份与开始

- `sessionID` 标识线程；`AgentSession.turnID` 单独保存当前跟踪的轮次。`context` 始终保留所展示事件的原始观察语义。例如 SessionEnd 的 context 没有 turn，快照仍可保留之前已知的 turnID。
- 首次观察可以是开始、工具、权限请求或完成通知。适配器缺失开始事件时，首个带 turn 的有效观察仍能建立该会话的轮次。
- 已有明确 turn 后，只有 `turnStarted` 或带 turn 的手动 `working` 状态可以开始另一个轮次。不同 turn 的普通工具、完成通知和无 turn 的更新均不能替换它。
- 未退出会话中，未知其他 turn 的观察先进入有界暂存，不改变当前快照；显式开始绑定该 turn 后，按原到达顺序重新处理其暂存观察，避免完成通知先到、开始事件后到时丢失完成状态。内部绑定回放不再次经过外部 UUID 去重。
- 切换时把上一轮加入退役窗口；窗口内旧轮的迟到开始、工具、完成通知都忽略，不更新当前快照或推进当前轮的时间。
- 新开始与当前轮最早已知观察的时间比较，避免上一轮迟到工具的更晚时间阻挡新轮开始。完全相同的开始时间按已观察到的到达顺序处理，不按 turn ID 的字典序猜测真实轮次。
- 同一 turn 的迟到或重复开始仅补充内部边界，不覆盖工具、待处理或终态。

## 同轮状态与工具

已识别轮次的终态不会被后续工具或同轮开始重新打开。终态证据的保守优先级为 `completed < interrupted < failed < ended`；后续更强的终态可以升级已有终态。`failed` 仍需显式手动来源，本规则没有增加自动整轮失败推断。

同轮完成、中断或显式失败可以胜过接收时间更晚的工作事件。状态的 `updatedAt` 表示当前展示事件的时间，因此可能回到较早的终态观察时间，不等同于进程最近活动或最后一次文件 I/O。

工具调用按 `toolUseID` 记忆 started / finished。已返回调用的重复返回、迟到开始和已开始调用的重复开始会忽略；对应调用的完成可以覆盖它接收时间更晚的可见开始。轮次切换后工具状态重建，调用 ID 可以在另一个 turn 中重新出现。

当前等待权限时，工具开始不会清除等待。已观察到的同名未完成工具构成候选集合，候选返回后再恢复工作；并行的其他调用不会清除这些候选。缺少 PreToolUse 时，只能使用后续同名 PostToolUse 作为恢复依据。

对于完全相同时间的同轮非终态，采用 `turnStarted < working / toolStarted < toolFinished < needsInput` 的保守优先级；权限等待与返回同毫秒时保留等待。完全相同优先级再按 UUID 稳定打平，这只是可重复的展示选择，不证明执行先后。

## 退出与旧版本兼容

SessionEnd 是会话级事件，按可见状态时间检查后关闭会话，保留已知 turn。退出后，普通工具事件不能重开会话；后续明确的新轮开始可以恢复。

v1 和缺少 turn 的 notify 继续可读。没有明确轮次的会话沿用时间与保守打平规则；建立明确轮次后，无身份更新返回 `missing-turn`，避免把旧通知归到当前轮。需要手动更新已识别轮次时，使用 CLI 的 `--turn` 参数；已结束轮次的重新工作应使用新的 turn ID。

## 有界历史与结果

每个会话保存最近 512 个有效事件 UUID、64 个退役 turn ID、当前 turn 最近 256 个工具调用 ID，以及 64 条尚未绑定开始的其他 turn 观察。窗口使用确定性的 FIFO 淘汰，不依赖系统时钟。被状态规则忽略的有效事件同样进入 UUID 窗口，避免被外部重复提交；无效事件不进入窗口。暂存观察只在对应 turn 绑定时由内部回放消费，超出暂存窗口的观察不保证保留。

这些窗口在当前进程中限制内存，并由 T011 的有界元数据 checkpoint 保存槽位、淘汰指针、工具 / 权限和未绑定观察，重启后继续使用相同边界；导入摘要避免旧磁盘文件重复回放。T009 治理原始磁盘历史，清理前保存现有轮次保护。窗口外、未保存或主动清除的历史仍不提供无限恢复保证，见 [会话持久化](session-persistence.md)。会话展示存活 / 过期仍使用 T007 投影，不能用窗口证明进程存活。

`apply(_:)` 保持原有 Bool 接口，返回 true 时可发布新快照；`applyResult(_:)` 返回可诊断的 `SessionEventDecision`。回放报告将其输出到 `registryDecision`；fixture 的 expect 可选声明同名字段。

| 结果 | 含义 |
| --- | --- |
| `applied` | 已应用到展示快照 |
| `duplicate-event` | UUID 在当前会话窗口中重复 |
| `retired-turn` / `unknown-turn` | 已退役轮次 / 未观察到开始的其他轮次 |
| `missing-turn` | 缺少身份，不能归到当前已识别轮次 |
| `turn-already-started` | 当前轮次的开始不再改变展示状态 |
| `terminal-turn` / `session-ended` | 工作事件不能重新打开终态轮次 / 已退出会话 |
| `outdated-tool` | 工具调用生命周期重复或倒退 |
| `waiting-for-input` | 当前工具观察不足以清除权限等待 |
| `older-event` / `timestamp-tie` | 事件较早 / 相同时间下未胜出 |

## inbox 顺序与能力边界

`EventInbox.readRecent` 仍读取最近的有界文件集合；处理顺序为事件时间、文件修改时间、UUID。文件修改时间只代表本地发布线索，最终 UUID 打平只保证稳定，不提供上游因果顺序。复制或改写文件修改时间也不能重建真实执行顺序。

Codex 0.169.0 的 hook / notify 没有源时间，turn ID 也不携带时序。尚未观察到的旧开始如果以更晚接收时间出现，无法与真正新开始完全区分；退役轮次保护只覆盖已经观察到且仍在窗口内的身份。

PermissionRequest 没有 tool_use_id，当前快照保存最近一个待处理观察，多个独立权限请求的精确关联 / 计数尚未实现。SessionEnd 没有 turn 或进程实例身份，无法精确区分旧进程退出与当前进程退出。上述来源限制保留在进度 K013，后续结合更完整事件来源及会话存活研究处理。

macOS 27.3 的原生运行、真实 hooks 启用及会话新鲜度验收继续分别记录。可复现回归见 [事件回放](event-replay.md)。

T013 的可选 Wave 位置与当前已应用观察一同替换；忽略事件不能改址，正式应用缺位置的事件会清空旧目标。未绑定观察的位置只在对应观察正式应用时生效，见 [位置协议](wave-location.md)。
